# template/.dockerignore

**What it is:** the files Docker leaves out when it builds the app's image from the project folder (`COPY . .` in the `Dockerfile`). It keeps the image small, and keeps secrets and data out of it.

**What's in it:**

- **Tool output:** `.git`, `.venv`, `__pycache__`, the pytest, Ruff and coverage files.
- **Secrets, in any folder (`**/`):**
  - every file whose name starts with `.env`, with no exception: the image doesn't need `.env.example`
  - private keys and certificates (`*.pem`, `*.key`, `*.p12`, `*.pfx`, `*.jks`)
  - SSH keys (`id_rsa` and the like)
- **Django output:** `staticfiles`, `media` and `media-public`. The image collects its own static files, and uploads live in Docker volumes.
- **Backups (`*.dump`, `*.tar.gz`):** a backstop in case one lands in the project folder. They hold the whole database and every upload. The README keeps backups in `/var/backups/<slug>` instead.
- **`tests`:** production never runs them.

**Why `**/` matters:** without it, Docker only matches the top folder, so `config/.env` would slip into the image. `tests/test_ignore_files.py` checks this, using git's matching rules plus a check that every secret rule starts with `**/`.

Git doesn't read this file, so unlike `.gitignore` it needs no `.jinja` ending.
