# template/.gitignore.jinja → .gitignore

**What it is:** the list of files a new project's git never commits.

**Why `.jinja`:** git reads any file named `.gitignore`, even inside `template/`. A `.gitignore` there would apply its `.env*` rule to the starter's own files, and hide `template/.env.example.jinja` from git. So it's stored under another name. Copier renders it, which only drops a Jinja comment at the top, and saves it as `.gitignore`.

**What's in it:**

- **Python and tool output:** `.venv/`, `__pycache__/`, `*.pyc`, the pytest and Ruff caches, coverage files and `htmlcov/`.
- **Secrets:**
  - every file whose name starts with `.env`, in any folder (`.env`, `.env.production`, `.envrc`...), except `.env.example`. To commit another one, add a `!` line for it.
  - private keys, certificates and keystores (`*.pem`, `*.key`, `*.p12`, `*.pfx`, `*.jks`)
  - SSH keys (`id_rsa`, `id_dsa`, `id_ecdsa`, `id_ed25519`)
- **Django output:** `staticfiles/`, `media/` and `media-public/`.
- **Backups:** `*.dump` and `*.tar.gz`, in case one lands in the project folder.
- **Editors and the OS:** `.idea/`, `.vscode/` and `.DS_Store`.

**Checked by:** `tests/test_ignore_files.py`, which asks git itself whether each sample secret file would be ignored.
  - **Agent worktrees:** `.claude/worktrees/` (the git worktrees `claude -w` creates) and `.claude/settings.local.json` (per-machine Claude approvals), so neither is committed.
